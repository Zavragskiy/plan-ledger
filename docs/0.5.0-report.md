# plan-ledger 0.5.0 — отчёт для потребителей

Релиз: <https://github.com/Zavragskiy/plan-ledger/releases/tag/v0.5.0>
Закрывает #10 (структурный closeout), #11 (`plan-digest`) и #17 (`plan-run --done`) из эпика #4.
Формат задач обратно совместим: старые файлы читаются как есть, новые поля появляются только при
закрытии.

## Что появилось

### 1. Closeout на переходе в Done (#10)

Закрытие — один вызов, конверт машинный, проза остаётся в `--note`/Notes:

```bash
plan-task set TASK-3 --status Done --check-ac 1,2 \
    --outcome "parser split out; gate green" \
    --decision "kept module-level names for the test harness" \
    --followup "extend the mypy scope to src/extra" \
    --files src/parser.py --tests "pytest tests/test_parser.py"
```

- `--outcome` обязателен на переходе в `Done`; `--force` — осознанное исключение, гейт его видит.
- `closed_date` пишется ровно на переходе и не двигается правками `--note`/`--owner`/`--slug`.
  Именно от него считаются retention и `plan-digest --since`, а не от `updated_date`.
- Повторное подтверждение `Done` с флагом **заменяет** блок, а не дописывает абзац (проблема
  «два разных merge-коммита в одной заметке» из отчётов).
- `evidence = {shard, result, commit}`: состояние приёмки в момент закрытия плюс короткий HEAD
  (вне git-чекаута commit опускается).
- Гейт: новый неблокирующий класс `no-closeout` (`summary.no_closeout`), исторические `Done` не
  переписываются; `plan-check --strict` поднимает его до exit 2.
- `plan-task show` печатает блок, `plan-task list --json` отдаёт `outcome` и `closed_date`.

### 2. `plan-digest` (#11)

```bash
plan-digest --active --limit 10     # открытая работа, максимум 10 строк
plan-digest --task TASK-23          # эта задача + Done-задачи с тем же шардом/файлами
plan-digest --since 90d --json      # недавние closeout для машины
```

- одна строка на задачу: `id, status, shard, ready, AC x/y, acceptance, outcome, closed`;
- итоги печатаются всегда и не зависят от `--limit`/`--status`:
  `total 30: done 16, open 14, stale 0, not confirmed 0, no closeout 2`;
- `shards proven: 2/3 of dodo.py` — ответ на «план ещё что-то доказывает?»;
- `hidden: 9 limit` — усечение явное, ничего не пропадает молча;
- без `detail` по умолчанию (`--with-detail` для отладки); компактный JSON — **3 197 байт** на
  30 задач.

### 3. `plan-run --done` (#17)

После мержа стадии `plan-check` показывает весь закрытый набор как stale, а `plan-run --all`
запускает ещё и контракты незапущенных стадий — они падают по устройству дерева и обрывают прогон.
Теперь:

```bash
plan-run --done
# shards of Done tasks: s6b s7 devloop s8 ...
# skipped (not Done): live probe sim state-owner ...
```

## Изменения поведения — проверьте скрипты

1. **Переход в `Done` требует `--outcome`.** Автоматизация, которая звала
   `plan-task set ID --status Done` без новых флагов, получит отказ (exit 1) с подсказкой.
   Временный выход — `--force`, но гейт покажет `no-closeout`.
2. `plan-check --json` получил `summary.no_closeout`; строка `plan-status --json` может иметь
   `verdict: "no-closeout"`.
3. `plan-task list --json` получил `outcome` и `closed_date`.
4. Новая команда `plan-digest`; у `plan-run` появился `--done`.
5. Стоимость и бюджет диагностики из 0.4.2/0.4.3 не изменились (один `doit`-процесс на команду).

## Совместимость

- Старые файлы задач грузятся без изменений; `closed_date`/`closeout` появляются только при
  закрытии новой задачи.
- Исторические `Done` без closeout остаются `Done`; гейт печатает секцию `NO CLOSEOUT` и **не
  падает** без `--strict`. Это осознанная амнистия, а не потеря.

## Проверка

- 159 тестов; новые: round-trip closeout, отказ без `--outcome` и `--force`, замена блока,
  стабильность `closed_date`, класс `no-closeout` в гейте, `plan-digest` (итоги/limit/active/since/
  task/JSON), выбор шардов в `plan-run --done` и печать пропущенных.
- CI: ubuntu/windows × Python 3.10/3.13, сборка колеса и smoke-install на теге.
- `plan-digest --json` на 30-задачном плане: 3 197 байт, что укладывается в бюджет 4 КБ.
