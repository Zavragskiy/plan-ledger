# plan-ledger 0.5.1 — отчёт для потребителей

Релиз: <https://github.com/Zavragskiy/plan-ledger/releases/tag/v0.5.1>
Стабилизация после 0.5.0: два дефекта в том, что появилось в 0.5.0, один давний диагностический
баг и один маленький CLI-пробел. Закрывает #18, #19, #2, #14.

## Что исправлено

### #18 — `## Notes` больше не портится

Рукописная секция сохраняется дословно: абзацы, `**выделение**`, списки и пустые строки переживают
`plan-task set`. Раньше каждая строка становилась буллетом, а `lstrip("-* ")` съедал ведущий `**`.
`--note` теперь дописывает буллет в конец секции, не трогая текст.

Важно: файлы, которые 0.5.0 уже переформатировала, инструмент восстановить не может — исходный
текст есть только в git (`git show <commit>:backlog/tasks/<file>.md`). У пострадавшего D7 это
коммит `334ac67`: там closeout записан уже поверх испорченного текста, поэтому искать нужно
предыдущую версию файла.

### #19 — `evidence.commit` стал `head_at_close`

Поле всегда означало HEAD **на момент закрытия**, то есть родителя коммита с closeout, а не коммит
изменения. Теперь оно так и называется. Старые файлы читаются (ключ `commit` мапится при чтении и
переименовывается при следующем сохранении).

Добавлен `plan-task set ID --refresh-evidence`: пересчитывает `{shard, result, head_at_close}`, не
трогая статус и остальной блок, — так указатель можно поправить после коммита closeout.

### #2 — отсутствующая doit-БД больше не выдаётся за изменённые файлы

Когда `.doit.db*` нет вовсе (свежий clone, CI без `plan-run`), `detail` теперь:
`no acceptance in this environment: <shard> has no doit database (run plan-run <shard>)`.
Вердикт остаётся `stale` — шард по-прежнему не доказан, но причина названа честно. Раньше
печатался список всех `file_dep` как «изменившихся».

### #14 — текст acceptance правится из CLI

```bash
plan-task set TASK-3 --ac-text 2 "pytest tests/domains/scan/test_x.py"
plan-task set TASK-3 --ac-replace "pkg/scan" "pkg/domains/scan"
```

`--ac-text N TEXT` меняет текст критерия, сохраняя отметку `[x]`; `--ac-replace OLD NEW` заменяет
подстроку во всех критериях и печатает число замен (ноль — не ошибка). Неверный номер критерия —
чистый отказ.

## Миграция

- Notes: ничего делать не нужно, если секция не была испорчена; испорченную — вернуть из git.
- `evidence.commit`: читается, переименовывается при следующем сохранении задачи.
- Новые флаги аддитивны: `--ac-text`, `--ac-replace`, `--refresh-evidence`.
