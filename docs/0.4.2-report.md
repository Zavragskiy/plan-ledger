# plan-ledger 0.4.2 — отчёт для потребителей

Релиз: <https://github.com/Zavragskiy/plan-ledger/releases/tag/v0.4.2>
Тема: стоимость и корректность. Форматы файлов задач не менялись, план 0.4.1 читается как есть.

## Коротко

| Что болело (из отчётов) | Что стало в 0.4.2 |
| --- | --- |
| `plan-status`/`plan-check` — O(задач) вызовов doit, 6–12 с на 24–60 задачах | 1 вызов на шард: 60 задач / 2 шарда — 0.53 с вместо 12.0 с |
| `plan-status` и `plan-check` по-разному считают `stale` (14 vs 0) | одно определение: stale — только `Done`; открытая задача — `not confirmed` |
| Порядок строк по имени файла, `NEXT` сравнивает ID как строки, `priority` игнорируется | один ключ: In Progress → priority → натуральный ID; `NEXT` уважает priority |
| `plan-run --all` молча пропускает шарды `dodo.py` без задач | покрытие берётся из `dodo.py`, такой шард всё равно прогоняется |
| `plan-status` шумит Done-строками и 10 путями в `detail` | `--open`, колонка `priority`, `detail` = 3 пути + счётчик, `--with-detail` |

## Замеры

Синтетический план: 60 задач, 2 шарда, по одному `file_dep` на шард, приёмка заселена
`plan-run --all`. Windows, Python 3.12, `time` среднее из двух прогонов.

| Команда | 0.4.1 | 0.4.2 | Ускорение |
| --- | --- | --- | --- |
| `plan-status` | 12.0 с | 0.53 с | ~22× |
| `plan-check` | 11.5 с | 0.53 с | ~21× |

Стоимость больше не зависит от числа задач в шарде — только от числа шардов: 60 задач
на 2 шардах стоят 2 вызова `doit info`. Кэш живёт один вызов команды и сбрасывается по
mtime БД, поэтому правка файла и `plan-run` в том же процессе видны сразу.

Согласованность `stale` после правки `file_dep` (открытые задачи, приёмка не перезапускалась):

| Версия | `plan-status` | `plan-check` |
| --- | --- | --- |
| 0.4.1 | `stale: 30` | `stale: 0` |
| 0.4.2 | `stale: 0`, `not confirmed: 30` | `stale: 0` |

Диагностика при 350 `file_dep` (30 задач, шард без прогона): `plan-status --json`
14 722 → 11 049 байт; `detail` у 30 строк стал `null` (151 символ на строку), полный
список — `--with-detail`.

## Что именно изменилось

- **#5, кэш приёмки.** `acceptance_status` мемоизируется по `(dodo, БД, mtime БД, шард)`
  на время одного вызова команды; `plan-status`, `plan-check`, `plan-shard list` и
  предупреждение в `plan-run --all` используют один и тот же кэш.
- **#6, порядок.** `planlib.model.sort_key`: `In Progress` → `high`/`medium`/`low` →
  натуральный id (`TASK-8` < `TASK-13` < `TASK-1000`). Применяется в `plan-status`,
  `plan-task list` и `plan-check`; `NEXT` — первая готовая открытая задача в этом порядке.
- **#7, вердикты.** `planlib/verdicts.py`: `classify()` и `detail_for()` — единственный
  источник `ok | stale | incomplete | unverified | open`. `plan-status --json` получил
  `verdict` у строки и `summary.unconfirmed`; `stale` теперь только про `Done`.
- **#8, покрытие.** `plan-run --all` = шарды из `dodo.py` + шарды, на которые ссылается
  план. Шард без задач прогоняется, в stderr — `dodo.py shards without plan tasks: … —
  plan-run --all runs them anyway`.
- **#9, представление.** `plan-status --open` (Done скрыты, счётчики по всему плану,
  `summary.hidden_done`), колонка `priority`, `detail` = первые три пути и `(+N more)`,
  `--with-detail` на `plan-status` и `plan-check` возвращает захваченный список
  (по-прежнему не больше `PLAN_LEDGER_MAX_LISTED`, по умолчанию 10).

## Изменения поведения — проверьте свои скрипты

1. `plan-run --all` теперь гоняет шарды `dodo.py`, на которые не ссылается ни одна
   задача. Если такой шард гонять не нужно — удалите его из `dodo.py`: декларация и есть
   покрытие.
2. `plan-status --json`: добавлены `verdict`, `summary.unconfirmed`, `summary.hidden_done`;
   `detail` у открытой задачи без ошибки окружения теперь `null` (раньше — строка
   `changed: …`). Кто парсил `detail` как всегда-строку, поправьте проверку на null.
3. `plan-check --json`: те же ключи, `detail` урезан так же; строки отсортированы тем же
   ключом, что и `plan-status`.
4. Кэш приёмки не переживает команду: `plan-check` после `plan-run` в отдельных процессах
   ведёт себя как раньше.
